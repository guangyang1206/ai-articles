要点速览
一个 kex_exchange_identification 报错排查了 6 轮：密钥换行、暴力破解、服务端配置逐一排除，最后靠 ssh -v 定位到企业内网 HTTP 代理拦截 SSH 流量；纯静态站点最终用本地 deploy.sh 一键部署解决。
3
深度解读
六轮排查路径
从公司内部 CI/CD 平台凭证变量、多行私钥换行丢失，到服务器 SSH 暴力破解与安全加固，作者把服务端因素全部排除后才转向网络链路，问题并不在服务器。
真正的根因
开发容器的 SSH 默认端口被改成企业跳板端口 36000，且外网 SSH 都经过只懂 HTTP 的代理，握手被直接回以 502，笼统的报错把排查引向了错误方向。
简单场景用简单方案
纯静态个人站点不需要 CI/CD 的复杂度，本地 rsync 加健康检查的 deploy.sh 足够；经验是 ssh -v 先行、密文用 Base64 传递、公网服务器关密码登录。
